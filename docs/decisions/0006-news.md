# 0006. News pipeline in two stages

Status: Proposed.
Date: 2026-11-26.

## Context

No open dataset holds most new events. The news finds them. The pipeline
collects widely, filters and pre-fills with code, and publishes nothing that a
person has not approved. This record fixes the rules and the budget before any
code, so that every other ticket of this milestone builds on the same rules.

Facts that the decision depends on:

- GDELT allows "unlimited and unrestricted use for any academic, commercial,
  or governmental use of any kind without fee". Any use or redistribution of
  the data must include a citation to the GDELT Project and a link to its site
  ([terms of use](https://www.gdeltproject.org/about.html#termsofuse)).
- The GDELT theme list has no code for sabotage, espionage, disinformation or
  undersea cables
  ([theme list](https://data.gdeltproject.org/api/v2/guides/LOOKUP-GKGTHEMES.TXT)).
- GDELT's raw files have no limit, while its search API limits each call. The
  API figures (250 records a call, about one call every five seconds) are not
  verified: check them before use.
- A git-backed Hugging Face repository keeps deleted files in its history
  ([storage limits](https://huggingface.co/docs/hub/storage-limits), and
  [record 0003](0003-storage.md)).
- Links and facts are outside the press publishers' right
  ([EUR-Lex summary](https://eur-lex.europa.eu/EN/legal-content/summary/copyright-and-related-rights-in-the-digital-single-market.html)).
- Media Cloud allows 4,000 API requests a week and gives story URLs without
  text ([Media Cloud FAQ](https://www.mediacloud.org/documentation/faqs)).
- Clusters and canonical records are built by ticket #94. Step 4 below uses
  the matching method of that ticket.

## Decision

We find new events in the news with a pipeline of seven steps, in two stages.
Stage 1 is code and human review only. Stage 2 adds a language model for fine
triage, only if the gate below is met. The project publishes no row that a
person has not approved. No other ticket of this milestone starts before the
owner approves this record.

### Seven steps

1. Collect the previous day's GDELT GKG files once a day.
2. Store the kept rows in the private store, as fetched.
3. Reduce the articles to one candidate per story.
4. Attach a candidate that matches a known event to that event, as one more
   source. The matching method is the one of #94 (clusters and canonical
   records). This record sets no matching rule.
5. Pre-fill the other candidates by rules.
6. Review the candidates in one pull request, and log each decision.
7. Publish the merged rows as source `news`, under CC BY 4.0.

### Collector

We use GDELT's raw files, not its search API. Reason: the files have no limit,
while the API limits each call. The API figures (250 records a call, about one
call every five seconds) are not verified: check them before use.

We use free news sources only.

### Watch list

| Item | Content |
| --- | --- |
| Domains | Seven domains. Each has its GDELT theme and its title keywords per language. |
| Actor terms | Russia, Belarus, China, Iran, North Korea, and their services. |
| Keywords | Sabotage, espionage, disinformation and undersea cables. |

- An actor term ranks a candidate for review. It never decides if a row is
  kept. Reason: an in-scope event with no state named is in.
- Keywords carry sabotage, espionage, disinformation and undersea cables.
  Reason: the GDELT theme list has no code for them.

### Inclusion rule

- An event of a category in scope is kept whatever its attribution. Reason:
  most drone sightings name no state.
- An event with no state named, or with suspicion only, gets
  `attribution = none`.
- Terrorism and common crime with no state link stay out. Reason: they are
  another subject.
- A state link is a statement by a source. The project never infers a state
  from the nationality or origin of a perpetrator. When a source records a
  state for an event, the event takes that state as the source gives it, and
  `attributed_by` says who gives it.

### Stages

- Stage 1 is code and human review only, at no cost. Reason: GDELT's structure
  is known, so code can collect, group, match and pre-fill, and the reviewer
  does the fine triage.
- Stage 2 adds a language model for fine triage only if, after 14 days of
  stage 1, the queue averages more than 20 candidates a day or the reviewer
  accepts fewer than 30%. Under those lines a model is not worth its
  complexity.
- A model, if used, costs at most 5 USD a month. Reason: a paid service is
  acceptable only as a small cost that brings a large gain in quality. Each
  spend needs the owner's explicit yes.

### Article text and names

- Article text is never stored and never published, and no copied headline is
  published.
  - Text: a git-backed Hugging Face repository keeps deleted files in its
    history, so a retention period there would not be real.
  - Text and headlines: links and facts are outside the press publishers'
    right.
- Records do not name private individuals, suspects included. Reason: a wrong
  attribution can harm a person.

### Measures and targets

| Measure | Target |
| --- | --- |
| Reference set | 200 labelled candidates |
| Collection recall | At least 80% |
| Records that a model accepts and that are in scope | At least 90% |
| Drift | A figure 10 points under its level at switch-on for two weeks opens an issue |
| Configuration change | Must not lower the score |

### Fallback

Media Cloud is a second collector, used if recall falls short. Reason: a free
tier can change or disappear. Media Cloud allows 4,000 API requests a week and
gives story URLs without text.

### Approval gate

No other ticket of this milestone starts before the owner approves this
record. Reason: every other ticket builds on its rules and its budget.

## Alternatives rejected

- GDELT's search API as the collector. The API limits each call, and the raw
  files have no limit. Its figures are not verified.
- A language model from the first day (stage 2 at once). GDELT's structure is
  known, so code does the collection, grouping, matching and pre-filling at no
  cost. A model is not worth its complexity under the stage 2 lines.
- Store article text with a retention period. A git-backed Hugging Face
  repository keeps deleted files in its history, so the deletion would not be
  real.
- Decide that an actor term keeps or drops a row. An in-scope event with no
  state named is in, so an actor term only ranks a candidate for review.

## Consequences

- Stage 1 costs nothing. The reviewer reads every candidate in the pull
  request until the stage 2 gate is met.
- A model needs the owner's explicit yes for each spend, and costs at most
  5 USD a month.
- The watch list of seven domains, with their themes and title keywords per
  language, is not set in this record. It must be filled before the collector
  runs.
- Step 4 depends on #94. The news pipeline cannot attach a candidate to a
  known event before that ticket is built.
- Review the collector if collection recall falls under 80%: Media Cloud then
  applies as a second collector.
- Review stage 2 when the queue or the acceptance rate crosses the gate lines
  after 14 days of stage 1.
